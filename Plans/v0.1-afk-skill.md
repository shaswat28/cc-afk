# Plan: cc-afk v0.1, the `/afk` skill

## Goal

Set the "I'm away, keep working" contract once, instead of hand-steering every run.
After `/afk <goal>` the session works unattended. It does not ask blocking questions.
It queues decisions in `QUESTIONS.md`, commits once per unit of work, and checkpoints
to `AGENTS.md`. It keeps going after compaction and context exhaustion, and it stops
cleanly when the work is done, it is blocked, or the user comes back.

Non-goals: pushing to remotes, opening PRs, picking new work beyond the stated goal,
changing permission settings, and replacing the user's `/handoff` skill.

## Facts this design relies on (official docs, checked 2026-10-10)

- **Stop hook.** It can return `{"decision":"block","reason":...}`, and the reason
  becomes Claude's next instruction. Its stdin has `session_id`, `cwd` and
  `stop_hook_active`. Claude Code ends the turn anyway after 8 consecutive blocks with
  no tool call in between. Stop does not fire on user interrupts.
- **SessionStart hook.** The matchers are `startup|resume|clear|compact`. Its
  `hookSpecificOutput.additionalContext` is injected into context. This is how the
  contract gets re-injected after auto-compaction.
- **No hook can see context usage** (only the statusline can). So "auto-handoff when
  context runs low" becomes: (a) state is always on disk because checkpoints are
  frequent, (b) built-in auto-compaction plus SessionStart(compact) re-injects the
  contract and state, and (c) `/afk resume` in a fresh session picks the run back up.
- **The user's `/handoff` has `disable-model-invocation: true`**, so the model cannot
  call it. `/afk` writes a `handoff.md` that follows the same template when the run
  ends.
- **No built-in setting keeps the model working.** Auto mode only removes permission
  prompts, and the skill tells the user to turn it on.

## State (in the project being worked on, not in the plugin)

`.afk/run.json` holds `status` (active|paused|done|blocked), `goal`, `session_id`,
`started_at`, `deadline` (optional), `max_continues` (default 40), `continues`,
`units_done`, `checkpoint_every` (default 3) and `last_head` (git HEAD at the last
continue). `/afk start` adds `.afk/` to `.git/info/exclude`, which keeps it local and
leaves the user's `.gitignore` alone. `QUESTIONS.md` sits at the project root and is
not committed unless the project already tracks it.

## `afk.py` subcommands

- `start --goal TEXT [--hours N] [--max-continues N] [--checkpoint-every N] --session ID`
  writes `run.json` and creates `QUESTIONS.md` with a header if it is missing. Then it
  prints the contract.
- `resume --session ID` rebinds the run to a new session and sets it active again.
  Then it prints the contract and state.
- `unit --summary TEXT` is called after each commit. It increments `units_done` and
  prints `CHECKPOINT DUE` every N units.
- `end --status done|blocked --reason TEXT` sets a terminal status.
- `stop` is run by the user and pauses the run. `status` prints the state.
- `hook stop` reads stdin JSON and prints a block decision or nothing. It allows the
  stop when: there is no run, the status is not active, the session_id does not
  match, the deadline has passed, or `continues >= max_continues`. It also allows
  the stop when the run made no progress (HEAD unchanged and QUESTIONS.md unchanged)
  across 3 consecutive blocks. That means the run is stuck, so the hook marks it
  `blocked`. Otherwise it increments `continues` and blocks with a reason. The reason
  restates the next step: pick the next unit, or call `end`.
- `hook session-start` reads stdin. If a run is active for this cwd, it emits
  `additionalContext` with the contract summary, the goal, the counters and the tail
  of QUESTIONS.md. For a `startup` source with a different session, it adds only a
  one-line note: "an /afk run is paused/active; `/afk resume` to continue".
- `hook prompt` (UserPromptSubmit) runs when the user types anything other than
  `/afk ...` while the run is active. It sets the status to `paused` ("user is back")
  and injects a note telling the model to summarise progress and open questions.

Every hook fails open: on any exception it exits 0 with no output, so the user is
never trapped.

## The contract (SKILL.md body)

1. Do not ask the user anything, and do not wait. When something is ambiguous, pick
   the reversible default, log it in `QUESTIONS.md` (question, options, choice, why,
   how to undo), and move on.
2. Work in units. One unit is one coherent change. Run its tests, then commit it with
   a plain message (follow the repo's attribution rules). Then run `afk.py unit`.
3. On `CHECKPOINT DUE`, rewrite the AGENTS.md "Current state" section in place (at
   most ~10 lines, no history) and the backlog status, if the project has them.
4. Never do these: push, force-push, rewrite history, delete user data, change
   settings or permissions, spend money, or send messages. Queue any of them in
   QUESTIONS.md instead.
5. When the next step would need one of those, or a real human decision, do all the
   other work first. If nothing is left, call `end --status blocked`.
6. When the goal is met and verified, run the full test suite, write `handoff.md`
   (the /handoff template), and call `end --status done`. Then give a short summary.
7. Context: keep tool output small. After compaction, trust `run.json`, git and
   QUESTIONS.md over memory.

Arguments: `/afk <goal>`, `/afk resume`, `/afk stop`, `/afk status`. Flags:
`--hours`, `--max-continues`, `--checkpoint-every`.

## Tests (each guards a real risk)

- The Stop hook allows the stop when: there is no run, the status is paused or done,
  the session differs, the deadline has passed, or the max continues is reached.
- The Stop hook blocks with a reason while the run is active and progressing, and it
  increments `continues`.
- After 3 blocks with no progress, the hook marks the run blocked and allows the stop
  (the trap guard).
- A malformed stdin or a corrupt run.json makes the hook exit 0 silently (fail open).
- SessionStart(compact) injects the goal and the QUESTIONS tail. For a foreign
  session at startup, it injects only the note.
- UserPromptSubmit pauses the run on a normal prompt and ignores `/afk` prompts.
- `unit` flags a checkpoint every N units. `start` writes `.git/info/exclude` exactly
  once.

## Execution

Implementation goes to one Sonnet 5.5 subagent at `effort: high` (the user's
ceiling). Claude (Opus) then reviews the diff, runs `make check` and
`claude plugin validate .`, and installs the plugin locally. It runs the Stop and
SessionStart hooks by hand with sample JSON, then commits to `main` and pushes.
